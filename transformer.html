AI 产品经理课程笔记：CNN、RNN、Transformer 与 Dify

2026-11-25 上午课堂 · 两份附件实为同一份课堂录音原文（哈希一致），已去重后整理要义

核心要点

  • CNN 擅长图像和视频，RNN 擅长文本和语音，二者不是取代关系（RNN 还略早出现）。CNN 看文本容易只抓局部、缺少记忆；RNN 能处理长文本，但太长会遗忘、计算量大。Transformer 既有局部并发扫描的能力，记忆也比 RNN 更好，出来后“一个打俩”，现在约 99% 的主流框架都用它。
  • Transformer 记住“输入—处理—输出”三阶段：输入做词嵌入（分词 + 词向量 + 位置向量后相加）；处理靠多头自注意力（多维度抓词与词的关系）和 MLP 多层感知器（延展、筛选、压缩）；输出按词表概率选出下一个 token，再并入前文循环，这叫自回归。
  • 对比题先说区别点：SFT（监督学习）给标准答案，RLHF（强化学习）只给对错；面试里一般说 SFT / RLHF，而不是“监督学习 / 强化学习”。SFT 要强调高质量样本，目标是提高泛化性；训不好常见于过拟合或欠拟合。训练模型还要记住三要素：算力、算法、数据。
  • 扩散模型分两步：先给图片逐步加噪直到变成“雪花屏”，再逐步去噪还原或生成新图，可做老照片修复、文生图，也可扩展到视频和音频。模型蒸馏是用已经训好的教师大模型产出答案（常带思考过程）去训练学生小模型，用更少算力学会部分能力。
  • 分清模型类别：LLM 只能文本对话；VLM 是给大模型“装上眼睛”，按“看、对齐、说”三步理解图片再回答。另有 ASR（语音转文本）、TTS（文本转语音）、OCR（从图提取文字）、Embedding（把自然语言译成数组）、Omni 全模态，以及偏实时渲染的世界模型。
  • 做 Agent 编排，课上选定 Dify：扣子有数据安全问题、早期只能用豆包；n8n 完全开源但过于自由、界面杂。Dify 介于二者之间，模块已封装，模型需自接 API，适合小白理解 Tool、MCP、编排和多智能体。周末先注册账号，下午实操；云端产品一般，主要价值是开源可本地部署。

一、工具与信息源

1. Aside 浏览器与 Kimi

  • 有同学在用 Aside 浏览器。讲师踩过坑：不要充它自己的 Pro 会员——下载一条抖音视频还没下完，额度就用尽了。
  • 更划算的做法是去订阅 Kimi（可连续包月或包年）。若坚持重度使用该浏览器，Plus 往往不够，Pro 或 699 元的 Max 才可能够用。
  • 在浏览器左下角设置里打开 Models：上方是订阅类模型（已有 ChatGPT、Claude、Gemini 等会员，可直接用会员额度）；下方是 API 接口，按调用计费，更烧钱。性价比最高的是把 Kimi Code 添加进去，按提示跳到 Kimi 完成一次授权即可。
  • 常见用法：只要网页能打开，就可以爬取解析视频（B 站、YouTube 等）；把做好的视频或文章同步发布到快手、小红书等多个平台；在网页上改表格、加字段；给自研产品做验收和测 bug。讲师用它走完 Lollipop 模拟面试站点的全流程，浏览器能自己合成机械语音操作，目前觉得还没有平替。
  • 提示词一定要交代清楚：讲师曾让它把抖音视频搬运到小红书和快手，没限制数量，结果一夜连发了 7、8 条。理论上网页上能做的事它都能做，但指令含糊就会失控。

2. 一手信息与多模型协作

  • 新工具、新方法大多第一时间发在 X（Twitter）上，能接触到一手信息，但新品往往有 bug、不流畅，没事可以去逛。
  • 近日较火的是博主数字生命卡兹克公布的 Agent 用法：把三家模型绑在一起——Claude 做主控（全面发展，但有时会反驳，大项目里会粗心漏项）；Gemini 负责审美和自然语言交流（三家里幻觉最高、谄媚最强，但文本体验目前被认为全球第一，能给情绪价值，又不同于豆包那种“纯二愣子”）；GPT 负责代码测试、审核和提交（像学霸，话不好懂，但干活稳、测试和审代码很强）。

3. 学习与做讲解视频的方法（课间同学分享）

  • 先用 Gemini 做第一手了解，主观上觉得能讲清楚后再问豆包；若豆包说得不对，把 Gemini 的回答贴过去校正，最后让豆包根据整段对话总结，并写出给小白看的视频提示词。
  • 豆包与即梦同属一个生态，可在豆包工作里登录即梦账号，在云端生成素材（例如 5 段、每段 5 秒），再导入剪映加工。豆包更适合跑流程，生成内容质量不如 Gemini。
  • 要控制成本：有同学 30 元约 700 积分，5 段 5 秒视频就用掉 300 多积分。术语很多，不必每个都钻到做一小时视频、再研究一小时，否则效率偏低。

二、SFT 与 RLHF 的区别（面试答法）

  • 遇到“A 和 B 的区别”这类题：先用一句话说清区别点，再展开关键词。
  • 区别点：SFT（监督学习）是给标准答案，让模型对照高质量样本学习；RLHF（强化学习）是只给对错或奖惩，让模型自己调整。课堂上用“训狗”类比强化学习。
  • 面试或回答时，一般不说“监督学习 / 强化学习”，而说 SFT 和 RLHF，这是常用的专业说法。
  • 讲 SFT 必须提到高质量数据集 / 样本，投喂目的是提高模型的泛化性。模型训不好通常有两种：过拟合、欠拟合。
  • 讲强化学习时，要提到 Reward Model（奖励模型）：用它做排序或判断对错，再据此标注、整理数据，继续训练模型。

三、CNN 与 RNN

1. 分组讲词要点

  • 深度学习的“深度”体现在多层隐藏层和神经元。最初是全连接网络：一张图的每个像素都喂给每个神经元。以 100×100 图为例，每层每个神经元要吃 1 万个数据，神经元一多就会参数爆炸。
  • CNN（卷积神经网络）假设邻近像素有关联，用小窗口（卷积核）一块一块扫描图像，并可同时用多个窗口并行扫，从而大幅压缩参数、降低算力需求。类比：拿放大镜一块一块看，而不是一个像素一个像素灌进去。它解决的是空间网格结构的数据，主要是图像。
  • 应用：人脸识别、自动驾驶等图像任务，也可分析心电图这类波形。在扩散模型里可参与加噪 / 去噪，也可作为视觉语言模型里处理图像的部分。
  • RNN（循环神经网络）针对序列数据（语音、文本）。初代网络读完“2”可能就忘了前面的“1”；RNN 增加隐藏状态（hidden state），相当于短期记忆：读当前内容时会带上已存储的前文，再把当前结果写回记忆。例如先读“我饿了”，再读“想吃饭”，就能把两句连起来理解。
  • 应用：语音翻译、文本处理等。

2. 讲师补充：关系、局限与 Transformer 的位置

  • 网上常把 CNN → RNN → Transformer 说成取代关系，这是错的。二者不是取代关系，RNN 还比 CNN 更早一点出现，只是各自擅长的方向不同。
  • CNN 不是不能做文本，RNN 也不是不能做图像，只是不擅长。CNN 看文本像拿放大镜只看局部，没有记忆，难以连成全局，遇到转折句（如“我不喜欢吃鱼，我特别喜欢养鱼”）容易抓偏，出现灾难性遗忘。RNN 做图像可以，但不擅长。
  • 训练大语言模型以文本为主：用 CNN 的局限是只抓局部；用 RNN 处理长文本“可以，但太长不行”——计算量大，存在梯度遗忘，只能依据已生成的前文回看，后面更容易出幻觉。后来出现 LSTM 等变体来管理记忆，属于亡羊补牢，对超长文本仍不够好。
  • Transformer 既具备并发地、像放大镜那样看局部的能力，又具备比 RNN 更好的记忆，因此把前两者都比下去，成为约 99% 的主流算法框架。课堂提到它也有短板：消耗算力高、需要海量数据、在小数据上不如前两者、内容不保证真实、黑盒、生成偏慢等。架构细节本节后半重点拆。
  • 学到什么程度即可：对底层原理有印象，能说出一些，不必到能完全展开的深度。分组讲词因角度不同会“一脚浅一脚深”，目的是让尽量多的人听懂。
  • 职场认知补充：公司里吸烟角往往比茶水间、下午茶更能听到一手动向（算法、产品、管理层常在此交谈，也可能听到人事变动）。这类技术概念至少要知道对错边界，避免在旁边听到“用 CNN 做文本”时说死、班门弄斧。

四、Diffusion 扩散模型

  • 过程分两步。第一步（加噪）：给一张清晰图一点点加噪点，从能认出“这几个点是多余的”，逐步加到完全看不出原图的雪花屏（像老式电视雪花）。第二步（去噪）：倒着学，先从噪点很少的图开始练习去掉噪声，再逐步加大难度，直到给一张纯雪花图也能还原。
  • 应用：修复不清晰、有水渍的老照片；从纯噪声出发按文字生成新图（例如“生成一张某某正在讲课的图”，不是把文字本身画成图片）；视频是一帧帧图片，音频是波形，所以也可以生成视频和音频。
  • 生成结果是模型根据以往训练数据推演出来的新东西，不一定 100% 等于原图或完全符合期待。去噪过程像对着原石一刀刀雕刻。讲师认为这次讲词再配群里的示意图就已经清楚，不再额外补充。

五、模型蒸馏

  • 大白话：小模型去“拜师”大模型，并不把对方全部能力搬过来，而是像蒸馏一样抽出某几项技能，用更少的算力、资源和时间学会。
  • 先分清前缀：同样叫“蒸馏”，对象不同含义就不同。例如把与某人的聊天习惯、语气压缩成一个 Skill，那是另一种蒸馏（Skill 后面会讲）。这里讲的是模型蒸馏。
  • 教师模型（teacher model）如 GPT、Claude：按常规路径预训练，再加上 SFT、RLHF 等训出来，数据多来自昂贵的人工标注问答。学生模型（student model）此时是空的，投喂的不再是人写的答案，而是教师模型给出的答案，并且常常带上思考过程（如 DeepSeek 先展开再收起的灰色思考文字）。学生主要更新自身参数，学的是推理过程，而不只是最终结果。
  • 类比：讲师先自己学、清洗、沉淀方法论，再把结论教给学生。识猫的例子：不只告诉小模型“这是猫”，而是多次询问大模型的思考（例如约 80% 像猫、8% 像虎、2% 像其他），让小模型把这个过程拷贝下来。
  • 课堂上的行业例子：有说法称通义千问曾用大量 Claude 账号提问、导出对话，再做成 Excel / CSV，转成 JSON 作为训练数据；因账号过多被发现，Claude 对国内封禁更严，尤其锁定杭州（阿里总部所在地）的 IP。讲师把“对话 → 导出 → 表格 → JSON → 投喂自己的模型”这一步称为蒸馏。

六、模型类别：VLM 与其他模态

1. VLM（视觉语言模型）

  • 作用是把图像和文字结合起来，给大语言模型装上一双眼睛：能看，也能把看到的说出来。它不只是先识别图片再翻译成文字，而是让图片和文字在同一个语义空间里直接对话，是图像理解加语言生成。
  • 例子：拍一张冰箱内部的照片，模型要能说出“牛奶快没了，鸡蛋还有半盒”——人用眼睛看、用大脑组织成话，VLM 要让机器具备同样的动作。
  • 工作原理三步：看、对齐、说。① 看：视觉编码器把图片拆成小块，变成一串数字；② 对齐：投影层当翻译官，把视觉信息译成大模型能懂的语言；③ 说：语言模型当大脑，把图像信息和用户问题一起理解，生成文字答案。
  • 给图之后通常还会追问“图里有什么”。模型会先做解码和 caption（图像理解），再结合文本问题一起回答。
  • LLM 一般指只能文本对话的模型。DeepSeek 在较长时间里不能看图，上传图片甚至发不出去，直到约 4.1 才补上“看图 / caption”能力——这只是模型是否具备某一种模态，不是模型种类的全部。

七、Transformer 架构

1. 输入：词嵌入

  • 和模型交互的底层逻辑，是先把人话翻译成机器能懂的数字，处理完再翻译回来。
  • 输入四步，合称词嵌入（embedding）：① 分词；② 给每个词一个词向量（像身份证号，用来映射含义）；③ 再给一个位置向量（表示它在句中的位置）；④ 各向量相加，代表这一个词。真正落地时维度往往有几百甚至几千，数字会很长。
  • 处理层看到的是这串数字；处理完吐出的也是人看不懂的数组，到输出阶段再译回词。

2. 处理：多头自注意力与 MLP

  • 处理模块主要有两块：多头自注意力机制和 MLP（多层感知器）。
  • “多头”可理解为多维度。每个头从不同角度抓词与词的关系，例如：邻近 / 搭配关系、语义关联、结构或标点关系。常见头数基础是 8 个，也有 16 或 32 个。类比：两个人之间不只有师生关系，也可能是朋友、都爱喝咖啡等，要分维度看。
  • QKV（不必在课上把公式讲透）：输入先分词，每个词作为 Q（问题 / 搜索词），去匹配各词自带的 K（标签 / 键），再把相关的 V（值） 取回来。每个头都会做一遍 QKV。残差、层归一化、前馈网络等结构课堂明确先不深挖，避免绕进去。
  • MLP 做三件事：延展、筛选、压缩。例如“苹果”可能是水果，也可能是手机；在“苹果今年如果出 18 我就买”里，与“18”相关联，就筛掉水果义，留下手机义再压缩输出。MLP 也称 FFN（前馈神经网络），面试时可直接说两层 MLP，用来单独提炼每个词的特征。
  • 自注意力 + MLP 这一套不是只走一层，而是多次堆叠的 Transformer 模块。残差和层归一化的作用是保障深层训练稳定，知道这一点即可。

3. 输出：温度、Top-K 与自回归

  • 处理结束后会得到一张词表上的概率排序，用来猜测下一个字。把选出的字拼回去，再整段重走一遍，循环到整段话结束。模型回复里的每一个字，都要走完这一轮。这叫自回归：每生成一个词，就并入前面的上下文，再送回模型预测下一个 token，直到全部生成完毕。
  • 两个曾经很重要的参数。温度（temperature）默认一般是 1.0，比较均衡；拉高则概率更平均，输出更随机、更有创意，适合设计和写诗；拉低则高概率更高、低概率更低，更严谨，幻觉更少，适合金融、医疗。Top-K 只考虑概率最高的前 K 个候选，K 常默认 5 或 10，之外的词不再纳入。
  • 这两项在两三年前，在扣子一类 Agent 编排平台上常要手调；现在模型能力更强，用提示词就能要求“发散一点”或“我在做金融提案，请严谨一些”，参数多半已写死在权重里，了解即可，日常不一定再碰到。
  • 类比：输入法联想有点像非常简化的单头注意力——输入“我”后，下一个提示总与“我”相关。

4. 面试话术（课堂打磨版）

当用户输入问题后，首先会被分词，并转换成词向量和位置向量，也就是做一次 embedding 向量化，相加后得到代表每个词的数组，再送入多层堆叠的 Transformer 模块。每个模块先通过多头自注意力定位上下文中词与词的关系，再通过 MLP（多层感知器）用延展、筛选、压缩的方式提炼每个词的特征；残差和层归一化用来保障深层训练稳定。全部层处理完后，模型计算词表概率，输出下一个 token，再把该词并入前文，循环预测，直到生成全部回答。这个逐 token 生成的过程就是自回归。

讲解时不必主动展开残差、层归一化和 FFN 的内部细节，免得把自己绕进去。课堂还展示过训练完成后的大语言模型形态：就是一大堆数字矩阵。可视化网站可以把嵌入、多头 QKV、MLP、温度和 Top-K 走一遍，感兴趣可自行点开，并用浏览器或模型按自己习惯的类比做二次理解。

面试一句话：大模型聊天的底层是 Transformer：先把话向量化，再用多层的“自注意力 + MLP”处理，按概率一个 token 一个 token 自回归生成。

八、模型训练三要素与下午安排

  • 算力：不只是 GPU 芯片，还包括散热和训练所需的全部基础设施、硬件，加在一起才叫算力。
  • 算法：不只是 Transformer 这类技术架构，也包括训练方式和提示词调优等一切能提高模型性能的手段。
  • 数据：人工标注、清洗以及蒸馏得到的数据。数据还会再分成训练集、验证集、测试集，后面再展开。
  • 从 0 到 1 自己训一个大模型不现实。下午计划：算力和算法用现成框架、租云实例来解决；真正要学员准备的是一批安全可用的数据。Grok 等工具也能帮忙做数据，但课上仍要带大家用 Dify。

九、为什么选 Dify（对比扣子与 n8n）

扣子、Dify、n8n 曾是非常主流的三类 Agent 编排平台。课上最终选择 Dify，周末先注册账号（可用 Google 登录），不必先付费，后面接第三方模型即可；下午约 2:30 跟着操作。

1. 为什么不用扣子

  • 扣子是字节跳动的产品，一开始没有走开源路线。工作流和数据放上去，相当于在字节的后花园里裸奔，存在数据泄露和数据安全风险。
  • 早期不支持叠加其他模型，只能用豆包——工作流搭得再好，模型也差一截。后来用户少了才做开源，但仍是半开源：部分组件开放，最核心模块并未开放，企业在“扒”Agent 时也较少选它。
  • 课堂上提到其企业版已下架，个人版前景也不乐观。

2. 为什么很多公司不用 n8n

  • n8n 大约 2018 或 2019 年就有，当时还没有今天的这一波 AI。它由一名德国工程师做出，本业是自动化，要在已经有老大 Zapier 的领域里做事。
  • Zapier 是收费很贵的 SaaS 自动化平台，典型能力是多软件联动（例如银行卡扣费后，短信和邮箱一起通知）。这位工程师选择完全开源、社区共建，口号是“连接一切 API”，跟 AI 起初没有关系；AI 起来之后，它也能做 AI Agent，对工程师很自由，什么都可以改。
  • 过于自由也意味着容易乱，像微信公众号编辑器可以随便调字号和居中，反而不如飞书把标题样式写死来得舒服。再加上界面常被形容像蜘蛛网、不好看，很多公司用不明白，也就不用了。

3. 为什么最终选 Dify

  • 创始人是张路宇。课堂介绍：12 岁就开始做个人网站挣钱；后来做运维向的软件“飞蛾”，被 Coding 收购，Coding 又被腾讯云收购，他随之进入腾讯云，在汤道生手下做技术。他推崇 n8n 那样的开源精神，想做开源的 Agent 编排工具，与公司“要挣钱、难开源”的理念不合，于是离开，并带走当时腾讯云约 20 名 AI 技术骨干创业。
  • 团队起步十余人到二十人，至今规模据说仍不超过 100 人，在苏州；2024 年其工具增速已是全球第一。走开源路线：代码和框架在 GitHub 上公开，企业可下载后在内网本地部署，这才是主业；ToC 云端只是顺带——云产品本身做得一般，卡顿、崩掉、出 bug 都要忍。
  • 它夹在扣子和 n8n 中间：不像扣子把模型和配置全部包好、付费即可用那么“傻白”；也不像 n8n 所有底层参数都要自己调。模型 API 需要自接，基本模块已经封装好。对小白来说，正好用来快速理解 AI、Tool、MCP、编排、Multi Agent（多智能体）这些概念。这是课上最终选择它的原因。
